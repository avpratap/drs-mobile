# Release guide — flavors, backends, signing

Nothing secret lives in this repository. Every key, password and signing
asset below is supplied at build time from a git-ignored file or CI secrets.

## Flavors

| | dev | prod |
|---|---|---|
| Android `applicationId` | `in.drsdairy.customer.dev` · `in.drsdairy.delivery.dev` | `in.drsdairy.customer` · `in.drsdairy.delivery` |
| iOS bundle id | same as Android | same as Android |
| Home-screen name | DRS Dev · Delivery Dev | DRS Dairy · DRS Delivery |
| Icon | brand icon with a burgundy **DEV** band | brand icon |
| Default backend | local (`10.0.2.2:8000` Android emulator, `localhost:8000` iOS simulator) | **live** — `https://drs-backend-zvb1.onrender.com` |

Both flavors install side by side. `flutter run` / `flutter build` without
`--flavor` build **dev** (`default-flavor: dev` in each pubspec).

iOS: each flavor has `Debug-<flavor>`, `Release-<flavor>`, `Profile-<flavor>`
configurations and a `<flavor>` scheme (generated by
`tool/ios_flavors.py`, idempotent). The plain `Runner` scheme still builds
prod settings.

## Choosing the backend

Resolution order (see `DrsEnv.resolve`):

1. `--dart-define=DRS_API_BASE_URL=https://…` — explicit origin
2. `--dart-define=DRS_API=live` or `DRS_API=dev` — named backend
3. the flavor's default (prod → live, dev → local)

```bash
# dev app against the deployed backend
flutter run --flavor dev --dart-define=DRS_API=live
# dev app against a backend on your LAN (physical phone)
flutter run --flavor dev --dart-define=DRS_API_BASE_URL=http://192.168.1.20:8000
```

`prod` refuses to start with a non-`https` URL (the "App misconfigured"
screen). The About screen shows the flavor and backend in use.

## Build-time values

Copy `env/prod.example.json` to `env/prod.json` (git-ignored), fill it in,
and pass it with `--dart-define-from-file=../../env/prod.json`:

| Define | Needed for |
|---|---|
| `DRS_RAZORPAY_KEY_ID` | live payments (publishable key id only) |
| `DRS_FCM_SENDER_ID`, `DRS_FIREBASE_*` | push — register **each bundle id** (prod and `.dev`) as an app in Firebase; see `docs/PUSH_NOTIFICATIONS.md` |
| `DRS_GOOGLE_MAPS_API_KEY` | delivery-app map (restrict the key to the app ids) |
| `DRS_PRIVACY_URL` | full privacy notice web page (About → Privacy notice) |
| `DRS_GRIEVANCE_EMAIL` | DPDP grievance contact shown in the privacy notice |

Do **not** put signing passwords in dart-defines: they are compiled into the
app binary.

## Android signing

Create an upload keystore once (keep it and its passwords in your password
manager / CI secrets, never in git):

```bash
keytool -genkeypair -v -keystore drs-upload-keystore.jks -alias upload \
  -keyalg RSA -keysize 4096 -validity 10000
```

Then either

- **CI:** set `DRS_ANDROID_KEYSTORE_PATH` (write the base64 secret to a file
  first), `DRS_ANDROID_KEYSTORE_PASSWORD`, `DRS_ANDROID_KEY_ALIAS`,
  `DRS_ANDROID_KEY_PASSWORD`, and `DRS_REQUIRE_RELEASE_SIGNING=true` so a
  missing key fails the build instead of producing a debug-signed bundle; or
- **local release machine:** copy `env/android-signing.example.properties`
  to `apps/<app>/android/key.properties` (git-ignored).

```bash
cd apps/customer_app
flutter build appbundle --release --flavor prod \
  --dart-define-from-file=../../env/prod.json
# -> build/app/outputs/bundle/prodRelease/app-prod-release.aab
```

Without a keystore, release builds are signed with the debug key (fine for
local testing, rejected by Play). Use Play App Signing; the key above is the
*upload* key.

## iOS signing

1. In the Apple Developer portal create App IDs `in.drsdairy.customer`,
   `in.drsdairy.delivery` (and the `.dev` ids if you distribute dev builds)
   with the **Push Notifications** capability.
2. Create App Store provisioning profiles for them.
3. Copy `apps/<app>/ios/ExportOptions.example.plist` to
   `ios/ExportOptions.plist` (git-ignored); set `teamID` and the profile name.
4. In Xcode → Runner → Signing & Capabilities, select the team for the
   `Release-prod` configuration (or set `DEVELOPMENT_TEAM` via
   `xcodebuild` / CI) — the project ships without a team id.

```bash
cd apps/customer_app
flutter build ipa --release --flavor prod \
  --dart-define-from-file=../../env/prod.json \
  --export-options-plist=ios/ExportOptions.plist
```

For CI, import the distribution certificate (`.p12`) and profile from
secrets into a temporary keychain, and upload with an App Store Connect API
key (`AuthKey_*.p8`) — all git-ignored.

## Versioning

`version:` in each app's pubspec (`0.1.0+1`) drives `versionName`/
`CFBundleShortVersionString` and the build number; bump the `+N` for every
store upload. The About screen shows both.

## Icons and splash

Source art lives in `branding/`. After changing it:

```bash
python3 tool/make_brand_assets.py      # re-render branding/*.png
tool/launcher_assets/generate.sh       # regenerate platform icons + splash
```

## Smoke test against the live backend

`packages/drs_api/tool/smoke_live.dart` drives the generated, typed client
against a running backend (default: the live one). It is read-only, prints
only step names, status and counts (no phones, OTPs, tokens or personal
data), and fails on any HTTP error or contract mismatch.

```bash
cd packages/drs_api
dart run tool/smoke_live.dart                                  # public catalogue + reviews
SMOKE_CUSTOMER_PHONE=<test customer> SMOKE_RIDER_PHONE=9999900003 \
  dart run tool/smoke_live.dart                                # + sign-in flows
dart run tool/smoke_live.dart http://localhost:8000            # any other backend
```

Sign-in steps need a backend that returns `dev_otp` (non-prod); against a
prod backend they are skipped. The first request may take ~1 min while a
free-tier host wakes up.

## Pre-release checklist

- [ ] CI green (analyze, tests, goldens, Android dev/prod, iOS dev/prod)
- [ ] `env/prod.json` filled; Firebase apps registered for the prod ids
- [ ] `DRS_PRIVACY_URL` and `DRS_GRIEVANCE_EMAIL` set
- [ ] `tool/smoke_live.dart` passes against the live backend
- [ ] Manual pass on the prod build against the live backend (sign in,
      browse, cart, checkout with a Razorpay test key first)
- [ ] Version/build number bumped
